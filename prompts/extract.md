## 작업 규칙
1. 입력에 실제로 적힌 내용만 사실(facts)로 기록합니다. 해석이나 추측은 넣지 않습니다.
2. 사실마다 F1, F2 … 순서로 ID를 붙이고, 어느 입력 칸에서 나왔는지 source 에 적습니다.
3. 효능, 테스트 완료, 인증, 순위, 수상처럼 증빙이 필요한 주장인데 '인증·증빙 자료' 칸에 해당 증빙이 없으면 needs_evidence 를 true 로 합니다.
4. 후기는 여러 사람이 반복해서 언급한 장점을 묶어 '후기' 유형의 사실로 정리하고, 몇 건에서 언급됐는지 함께 적습니다.
5. 상세페이지를 현지화하는 데 필요하지만 입력에 없는 정보를 questions 로 만듭니다.
   카테고리 핵심 정보 목록을 참고해 빠진 항목을 찾고, 판매 국가에서 특히 필요한 정보(예: 전성분, 용량, 원산지)를 우선합니다.
6. product_summary 는 확인된 사실만으로 2~3문장 요약합니다.

## 이미지가 함께 주어진 경우
7. 이미지마다 [이미지 I1] 같은 ID가 붙어 있습니다. 하나의 긴 상세페이지를 여러 조각으로 나눈 것일 수 있으니 순서대로 이어서 읽습니다.
   조각 경계에서 잘린 문구는 앞뒤 조각을 합쳐 한 번만 기록합니다.
8. images 에 이미지별 분석을 넣습니다. texts_ko 에는 이미지 안의 한국어 문구를 고치지 말고 원문 그대로 옮깁니다(위험 표현 검수에 사용됨).
   읽을 수 없는 글자는 추측하지 말고 '[판독 불가]'로 적습니다.
9. 이미지에서 확인한 사실도 facts 에 넣고, source 에 이미지 ID를 적습니다(예: '이미지 I3').
   텍스트 입력과 이미지의 내용이 서로 다르면(예: 용량, 함량) 둘 다 기록하고 questions 에 어느 쪽이 맞는지 묻습니다.
10. 이미지 속 수치·배지·인증 마크·'1위' 같은 주장도 증빙 자료가 없으면 needs_evidence 를 true 로 합니다.
11. issues 에는 현지 고객이 이해하기 어려운 표현(한국 유행어, 한국 기준 단위·인증, 한국어 말장난 등)과 근거 확인이 필요한 부분을 적습니다.
이미지가 없으면 images 는 빈 배열입니다.
